# Frozen evaluation and inspection

The metrics package accepts only validated immutable `ChoiceDefinition`, `DatasetSnapshot`, `LabelSnapshot`, and `ResultSnapshot` values. It rebuilds nested models before reading fields, then checks their cross-record case, dataset, decision, input-hash, question, and option relationships. It never reads current drafts, labels, providers, SQLite, or HTTP. A malformed record yields a safe incompatibility reason rather than a partial score.

`assess_results` preserves every selected case and reports status counts separately from set correctness. Coverage counts valid answers over all selected cases. Accuracy counts only valid answers with applicable labels, including acceptable sets. The ordered confusion matrix and per-class precision, recall, and F1 use only applicable single-label expectations. Each rate retains exact numerator and denominator; undefined rates have a null value and a reason. Legacy labels for retired questions remain visible with their disputed, stale, and incompatible causes. Native confidence is displayed as provider evidence, but not transformed into a calibration score.

The majority baseline fits once from the separately frozen full development dataset and its labels. It uses eligible single-label cases with valid input, chooses ties in frozen option order, and scores the same provider-valid labelled cases used by set accuracy, including acceptable sets. Snapshot IDs, support, selected splits, paired denominator, and fit/evaluation overlap are explicit. It cannot fit on mutable current labels or the selected test scope. No fit means an unavailable baseline, not zero accuracy.

`EvaluationService` uses the source's consistent snapshot capability to verify the manifest, frozen definition revision, selected and development snapshots, prepared cases, result identity, and content hashes. It saves an immutable `EvaluationRecord` with an operation-intent replay hash. `reevaluate_current_labels` copies current labels only from the run's decision and dataset scope into a new immutable label snapshot and evaluates the saved result in the same source transaction. It never compiles or dispatches requests. Later label edits and resumed answers cannot alter earlier evaluations. The original development fitting snapshots remain bound to the run.

Live latency uses only recorded fresh dispatched-call durations and nearest-rank p50/p95. Fixture timing stays undefined. Native usage totals are complete only when every dispatched live attempt reports token usage; partial reported sums and missing totals are distinct. Cost stays unknown until a trusted pricing source exists.

`ResultInspection` reads one frozen result/evaluation boundary. Lists retain selected/status counts even when filters yield zero cases. Case detail shows answer, expected options, exclusions, provenance, probabilities, native confidence, notes, and bounded attempt states. Request and response bodies are explicit opt-ins; credential fields and Bearer tokens are redacted through the pure contracts redactor. Provider adapters sanitize known secrets before persistence; inspection never resolves credentials. User annotations are separate append-only resources and do not change any result or evaluation hash.
